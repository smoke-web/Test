# Охотник за рилсами (reels_hunter)

## Роль
Следит за Instagram-аккаунтами в нише «выдуманные истории с цепляющим сюжетом»
и сразу сообщает в Telegram, когда у кого-то из них начинает «залетать» рилс:
набирает намного больше лайков, чем обычно у этого автора. Это сигнал, что ролик
ушёл к новой аудитории и, скорее всего, приносит автору подписчиков.

Цель хозяина — по этим находкам делать свои похожие рилсы (по мотивам, не копии).

## Как работает
- Запускается сам на GitHub Actions каждые 30 минут (`.github/workflows/reels-hunter.yml`).
- Берёт последние посты каждого аккаунта из `config.json` через официальный
  Instagram Graph API (Business Discovery). Работает только с аккаунтами «Автор»/«Бизнес».
- Рилс считается залетевшим, если он не старше `max_age_days`, у него не меньше
  `min_likes` лайков и в `outlier_multiplier` раз больше лайков, чем медиана по рилсам автора.
  Если рилсов у автора меньше `min_reels_for_baseline`, сравнивает лайки с числом подписчиков.
- Уже отправленные рилсы запоминает в `state/seen.json` и повторно не присылает.
- Просмотры рилсов чужих аккаунтов API не отдаёт — поэтому ориентир по лайкам.

## Гейты (когда спрашивать разрешение)
Нет. Агент только читает публичные данные и шлёт уведомления хозяину — ничего не
публикует и не тратит деньги. Разрешение не требуется.

## Правила
- Никогда не логировать и не коммитить токены. Они живут только в секретах GitHub:
  `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `IG_USER_ID`, `IG_ACCESS_TOKEN`.
- Не сканировать Instagram в обход официального API (без логина/пароля, без скрейпинга).
- Об ошибках (например, истёкший токен) сообщать в Telegram не чаще раза в 12 часов.

## Как менять
- Добавить/убрать аккаунт — правка списка `accounts` в `config.json`.
- Чаще/реже уведомления — `outlier_multiplier` (меньше = больше находок) и `min_likes`.
